# Deploying to Render for testers

Why: `shopify app dev` serves the Vite dev build through a temporary tunnel from
your own machine. It compiles each page on demand and the URL changes every run,
so it is the wrong thing for testers. This serves the production build from an
always-on host with a stable URL.

Files added: `Dockerfile`, `.dockerignore`, `render.yaml`, this guide.
Not verified here: the image was not built and the service was not started (no
Docker or network in the sandbox). Expect to fix small things on the first deploy.

## 0. Before you start
- Rotate the secrets that were pasted into a chat: the Shopify API secret
  (Dev Dashboard), the Neon database password. `JOBS_SECRET` is regenerated by Render.
- Never commit `.env`. If the project has no `.gitignore`, create one:

      cat >> .gitignore <<'EOT'
      node_modules
      build
      .env
      .env.*
      !.env.example
      .shopify
      .react-router
      dev.log
      EOT

## 1. Use a separate production app (recommended)
`shopify app dev` rewrites the app's URLs to its tunnel
(`automatically_update_urls_on_dev = true`). If testers use the same app, every dev
run would break their installs. So:

    npx shopify app config link

choose "Create this project as a new app", and name it e.g.
"India Legal Metrology & MRP (prod)". That writes a new
`shopify.app.<name>.toml` with its own `client_id`. In that file set:

    application_url = "https://india-legal-mrp.onrender.com"

    [auth]
    redirect_urls = [ "https://india-legal-mrp.onrender.com/auth/callback" ]

    [build]
    automatically_update_urls_on_dev = false
    include_config_on_deploy = true

and copy the `[[webhooks.subscriptions]]` blocks from `shopify.app.toml` into it.
The linked config you have now has NO webhook subscriptions, so deploying it as-is
would register no app/uninstalled, product or privacy (GDPR) webhooks. Use
`api_version = "2026-10"` under `[webhooks]` to match the code.
Replace the host with your real Render URL if it differs (step 3).

## 2. Create the service
1. Push the project to a private GitHub repository.
2. Render dashboard -> New -> Blueprint -> select the repository.
3. Fill the prompted values:
   - `SHOPIFY_API_KEY`, `SHOPIFY_API_SECRET`: from the PRODUCTION app.
   - `SHOPIFY_APP_URL`: `https://india-legal-mrp.onrender.com` (fix in step 3 if needed).
   - `DATABASE_URL`: Neon DIRECT connection string (host without `-pooler`).
4. Region is set to `singapore` in `render.yaml`; change it to match your Neon region.
5. `plan: starter` keeps the service awake. Free instances sleep after ~15 minutes.

First deploy runs `prisma migrate deploy`, then `npm start`. Check
`https://<your-service>.onrender.com/healthz` returns `{"ok":true,...}`.

## 3. Point Shopify at it
- If Render gave you a different hostname than `india-legal-mrp.onrender.com`,
  set `SHOPIFY_APP_URL` in Render -> Environment to the real one and update the
  two URLs in the production toml.
- Push the config and the theme extension:

      npx shopify app deploy --config <name-of-production-config>

  (`--config` takes the part of `shopify.app.<name>.toml` between the dots.)

## 4. Install on a test store
Open the production app from the Dev Dashboard and install it on a dev store
in your organisation. For testers outside your organisation, check the app's
Distribution settings in the Dev Dashboard; this guide does not cover that.

## Optional
- `SUPPORT_EMAIL` and `SHOPIFY_APP_REVIEW_URL`: add in Render -> Environment.
- The in-process job worker starts on the first admin page load. `/healthz` shows
  `queue.driver`.
- Logs: Render dashboard -> your service -> Logs.
